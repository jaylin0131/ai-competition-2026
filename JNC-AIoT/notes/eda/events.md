# 錯誤與維修事件總表（7 個場域）

> 整理日期：2026-10-20｜來源：`data/processed/*.csv`（用 `common.load_jnc.load()` 讀取）｜各場域細節見同資料夾的 `<site>.md`

## 先講清楚：CSV 裡沒有「錯誤碼」或「維修紀錄」欄位

7 個 CSV 都只有感測數值、設備狀態與用電，**沒有告警、錯誤碼、工單或維修紀錄欄位**（已列入待問事項 Q1）。
本表的事件都是**從數值推斷出來的**，每筆都附上判定依據與可信度。

不過有 4 類欄位本身就帶有「設備事件」的資訊，可以算是最接近紀錄的東西：

| 場域 | 欄位 | 可以看出什麼 |
|---|---|---|
| 育成北側 | 開機次數(次)、運轉時間(秒) | **重開機**：開機次數 +1、運轉時間歸零 |
| 三爺宮溪 | pH斜率、EC斜率、DO斜率 | **重新校正或模式切換**：斜率值改變 |
| 羊舍 | 帆布張／收、遮陽、風扇（16 欄） | **實際操作紀錄** |
| 魚塭 | CPM 系統總和功率 | **增氧機開關**（約 760 W＝運轉、約 17 W＝停機） |

## 可信度的意思

| 等級 | 意思 |
|---|---|
| **高** | 數值物理上不可能（例如夏天 −2.8°C），或設備欄位直接記錄（開機次數 +1） |
| **中** | 有明確型態（多支探頭不一致、長時間同一值），但原因有其他可能 |
| **低** | 推測（例如「疑似探頭清洗」），需要企業確認 |

## 事件類型

| 類型 | 判定方式 |
|---|---|
| 斷線 | 時間軸缺小時，或整列所有欄位都是 0 |
| 重開機 | 開機次數增加、運轉時間歸零 |
| 卡值（凍結） | 平常會變動的欄位連續 N 小時同一個值 |
| 飽和 | 停在量測上限（例如 PM10 119.6、TVOC 300） |
| 跳點 | 單一小時出現極端值，前後正常 |
| 漂移 | 同物理量的多支探頭逐漸分開，或數值長期往一個方向偏 |
| 探頭失效 | 掉到 0 或不合理的平線並持續 |
| 無效輸出 | 設備在特定狀態下輸出固定的假值 |
| 校正／維護 | 斜率改變，或多支探頭同時驟變後慢慢回穩 |
| 特殊操作 | 操作欄位出現平常沒有的值 |

## 怎麼用

1. **評估用的弱標籤**：可信度「高」「中」的事件可以當作真實故障，搭配合成故障注入來評估偵測模型（例如偵測 P12 pH1 漂移比目視提早多久）。
2. **物理規則清單**：「依據」欄就是規則的寫法，可以直接寫進感測器故障檢查。
3. **預測維護故事**：東北角 E04 → E07（提早約 44 小時）、魚塭 P14 DO2 劣化 → P16 維修，都是「偵測到劣化 → 派工 → 恢復」的完整案例。
4. **要問企業的問題**：P03–P16 的疑似維護是否屬實、R06 的 4.71 是不是錯誤碼、G02／G03 的狀態碼 2／4 意義、東北角 8/24 之後是否送修。若能拿到真正的維修日期，就能把可信度「低」的事件升級。
