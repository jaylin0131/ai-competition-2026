# 展示與備援錄影腳本

> 用途：(1) 3 分鐘特色介紹短片；(2) 12/11 初賽線上展示的備援錄影（平台目前只能在本機執行，網路或電腦出狀況時直接播放）。
> 數字依 [proposal-draft.md](proposal-draft.md)；畫面不可出現校名、校徽、系所、指導老師。

## 錄影前準備

1. 啟動平台（在 JNC-AIoT 資料夾）：

   ```bash
   .venv/bin/streamlit run app/streamlit_app.py
   ```

   第一次啟動要訓練預測模型約 2 分鐘，請提前開好；瀏覽器開 http://localhost:8501。
2. 確認側欄「決策參數」顯示 α = 0.1、未驗證（增氧決策需人工確認）。
3. 「執行回饋」頁先清除紀錄，避免出現排練時的資料。
4. 關閉通知、清空桌面與分頁；錄螢幕解析度 1920×1080。
5. 錄兩份：**完整版**（約 6 分鐘，備援用）與**剪輯版**（3 分鐘，特色介紹短片）。

## 分鏡（完整版）

| 段落 | 時長 | 操作 | 旁白重點 |
|---|---|---|---|
| 1 痛點 | 0:20 | 平台首頁五階段色塊 | 魚塭缺氧常發生在半夜；更麻煩的是探頭壞了，系統還照著錯的數字開機、告警 |
| 2 閉環總覽 | 0:30 | 指著五個色塊與「三個問題」 | 照銘祥流程圖：IoT 感測 → 大數據 → AI 分析 → 決策引擎 → 執行回饋；每一小時回答「現在發生什麼、接下來會怎樣、該做什麼」 |
| 3 探頭可信度（主打） | 1:00 | 側欄跳到「DO3 失效、氣象站凍結：9/20 06:00」→「狀態辨識」看可信度長條圖 →「異常診斷」看原因與證據 | 三支探頭互相比對，DO3 讀到 0 被判定失效、自動排除並派工；同一條開機規則，直接用原始探頭會有 286 小時無效告警，排除後是 0 |
| 4 注入故障 | 0:50 | 側欄「注入故障」選主機斷線（offline）→「決策與工單」 | 主機斷線時系統無法判斷水質，走 Fallback：PLC 維持增氧機運轉、派人檢查主機 |
| 5 預測與決策 | 1:00 | 跳到「預測性增氧：7/19 18:00」→「趨勢預測」看 1–6 小時曲線 →「決策與工單」看 9 欄決策 | 預測 6 小時內低溶氧機率，提前建議開備用增氧機；決策照企業 9 欄格式，中風險要人工確認 |
| 6 人工確認與回饋 | 0:50 | 按「核准」→「執行回饋」看紀錄與 3 小時後溶氧 → 按「重新學習」 | 核准後模擬送 SCADA 執行；系統檢查預警後來有沒有成真，再重新調整參數；成本沒有比基準省 5% 以上，就不放行自動執行 |
| 7 成效與誠實揭露 | 0:40 | 「成效驗證」頁 | 9/9 已知故障、合成故障 91%、預測誤差比持續法低約 10%；AI 只比調好的固定門檻略好，我們照實寫 |
| 8 收尾 | 0:20 | 回首頁 | 創新在整合與安全設計：先判斷探頭可不可信，再做決策 |

剪輯版：保留第 1、3、5、7、8 段，各段縮短，總長控制在 3 分鐘內。
